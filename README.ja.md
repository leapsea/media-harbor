# Media Harbor

YouTube と Instagram のコンテンツを自分の端末へ保存し、投稿者と日付で整理。プロフィールの新しい投稿も継続して取得できます。

## 主な機能

- 動画・投稿の単発ダウンロードと、プロフィールの定期確認。
- YouTube は最高画質の MP4 と追加の m4a 音声を保存。字幕、コメント、サムネイル、メタデータを選択できます。
- 取得済みのコンテンツをスキップ。未完了分の取得では既存ファイルを再利用し、不足分を取得して、選択したコメントとメタデータを更新します。
- 状態、進捗、ログ、履歴を確認。キャンセル、再試行、再起動後の処理再開に対応。
- ファイルの整理とアーカイブ。中国語、英語、ヒンディー語、ロシア語、日本語のインターフェース。

## 起動

### 方法 1：公開イメージを取得（推奨）

Docker をインストールします。ソースの取得は不要です。イメージの初回公開後に実行します。

```sh
docker pull ghcr.io/leapsea/media-harbor:latest
mkdir -p data downloads archive logs
```

Linux ではコンテナー起動前に所有者を設定します：`sudo chown -R 1000:1000 data downloads archive logs`。イメージの既定ユーザーは `1000:1000` です。

```sh
docker run -d --name media-harbor \
  --restart unless-stopped \
  -p 8080:8080 \
  -v "$PWD/data:/data" \
  -v "$PWD/downloads:/downloads" \
  -v "$PWD/archive:/archive" \
  -v "$PWD/logs:/logs" \
  -e TZ=Asia/Singapore \
  ghcr.io/leapsea/media-harbor:latest
```

[http://localhost:8080](http://localhost:8080) を開きます。この例は全フォルダーをマウントします。アーカイブやログ保存が不要な場合は該当する `-v` を外せます。

| ホストのフォルダー | 保存内容 | マウントは必須？ |
| --- | --- | --- |
| `data` | タスク、設定、Cookie、ダウンロード索引 | 起動には不要。コンテナー再作成後も状態を保持するため推奨 |
| `downloads` | ダウンロードファイル | 起動には不要。ホストでのアクセスとファイル保持のため推奨 |
| `archive` | アーカイブファイル | アーカイブ使用時は書き込み可能なマウントが必須 |
| `logs` | タスクログ | 任意。ホストでログを確認・保持する場合はマウント |

マウントしないデータはコンテナー内に保存され、コンテナー削除時に失われます。ポート変更は `-p 8080:8080` の最初の数値を変更し、パスは自分の保存先に置き換えます。

### 方法 2：ソースからビルド

Docker、Compose、Git をインストールして実行します。

```sh
git clone https://github.com/leapsea/media-harbor.git
cd media-harbor
cp .env.example .env
mkdir -p data logs downloads archive
```

Linux では起動前に `.env` の `PUID` / `PGID` に合わせて所有者を設定します。既定値の場合は `sudo chown -R 1000:1000 data logs downloads archive` を実行します。独自ユーザーは [デプロイ資料](docs/部署与开发.md#docker-配置) を参照してください。

```sh
docker compose up -d --build
```

## 最初のタスクを作る

### 動画や投稿を 1 件取得する

1. **タスク管理 → 新規タスク** を開きます。
2. プラットフォームを選び、コンテンツの URL を貼り付け、解析されたフォルダー名を確認します。
3. 保存する内容を選んで保存します。個別コンテンツの URL はすぐに 1 回実行されます。
4. タスク一覧で進捗を確認します。完了後は履歴からファイルを確認し、コピー操作で保存先フォルダーのパスを取得できます。

### 投稿者の新しい投稿を継続して取得する

1. プロフィール URL、フォルダー名、実行間隔を設定して保存します。
2. **初期取得** を押して、現在取得できるコンテンツを保存します。プロフィールのタスクは保存だけでは開始しません。
3. 最初の手動実行後に定期処理が始まります。その後は新規コンテンツだけをキューに追加し、定期処理の一時停止・再開もできます。

| 操作 | 用途 |
| --- | --- |
| 初期取得 | プロフィールの初回取得 |
| 増分スキャン | 新しい投稿の確認。初回取得にも使用可能 |
| 未完了分を取得 | 既存ファイルを再利用し、不足分を取得、選択したコメントとメタデータを更新 |
| 再試行 | 失敗したタスクの再実行 |

履歴のタグは実際のファイルに対応します。コメントはメタデータ JSON に保存され、両方のタグが同じファイルに付きます。**ダウンロード履歴を消去** は表示記録だけを消去し、ファイルと索引は保持します。その後のスキャンでも取得済み項目はスキップされます。

## よく使う設定

**設定** で変更してから **設定を保存** を押します。

| 分類 | 用途 |
| --- | --- |
| ダウンロード | プラットフォーム別の同時数と YouTube の既定内容。タスクごとに取得オプションを変更可能 |
| 保存先ルール | テンプレート、日付の取得元、アーカイブ。アーカイブには書き込み可能なマウント先が必要 |
| Cookie | エディターにブラウザーの Cookie を貼り付け。保存後は自動使用 |
| インターフェース | 言語、最近のダウンロード件数、ページ当たりの件数 |
| ストレージ | 使用量、ログ消去、完了済み・関連のないタスクのキャッシュ削除 |
| デバッグ | 少数の項目で試すための上限。全件処理は上限を無効化 |

既定テンプレートは `{platform}/{directory_name}/{year}/{month}{day}/{filename}`。日付はサイトのアップロード・公開日を使い、不明な場合はタスク作成日を使います。日付はローカル時刻で計算します。

イメージ直接起動時は起動オプションでポート・パス・タイムゾーンを変更し、ソースの Compose 起動時は `.env` を変更します。アクセスに失敗した場合はタスクログを確認してください。取得結果はネットワークとプラットフォームで利用可能な内容に依存します。

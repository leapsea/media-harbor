# Media Harbor · 版本 1 工程方案

## 一、需求与约束

核心域为订阅、扫描任务、内容下载和文件归档。目标是单用户单实例，SQLite 持久化，不设全局并发限制，YouTube 默认下载并发 2、Instagram 默认下载并发 10；扫描与下载分通道计数，每配置最多运行一个扫描，多个下载共享平台并发名额。周期任务每秒检查；媒体入队、任务结束、重试和并发设置变化通过合并通知立即触发调度，空闲下载名额及时补位。Dashboard 每 4 秒刷新。

任务创建、扫描、下载、文件归位和归档构成完整处理流程。任务状态持久化，运行错误进入任务日志，用户可取消或重试。

## 二、技术与分层

采用模块化单体和轻量 Clean Architecture。Go 标准 HTTP 库负责 API，Vue 3 + Pinia 负责界面，modernc SQLite 使多架构构建无需 C 工具链，robfig/cron 解释周期。没有 Redis 或消息队列，SQLite 任务表就是持久队列。

依赖方向为 `httpapi → service → domain`，`storage` 和 `engine` 实现领域接口。主程序通过构造函数注入适配器，不引入额外 DI 框架。

## 三、目录结构

```text
cmd/server/main.go          配置、依赖装配、生命周期
internal/
  config/                  环境目录与首次默认设置
  domain/                  实体、Engine 和 Repository 接口
  storage/                 SQLite Schema、唯一索引、事务写入
  engine/                  gallery-dl / yt-dlp / FFmpeg 命令集成
  service/                 调度、任务状态、目录检测、文件归位归档
  httpapi/                 HTTP CRUD 与日志、设置、Cookie API
web/src/
  stores/media.ts          服务器状态与统一请求逻辑
  components/              订阅编辑、YouTube 选项、系统设置
  App.vue                  工作台导航与概览、任务和历史页面
.github/workflows/         构建验证与 GHCR 发布
Dockerfile                 Vue、Go 构建与运行引擎
compose.yaml               端口、用户、独立存储挂载
```

## 四、模型与数据流

`Subscription` 保存稳定 ID、固定目录名称、当前名称、URL、周期及选项。`Content` 保存平台内容 ID、发布日期、状态和文件位置。`Task` 保存任务类型、尝试次数、运行状态和错误。

创建订阅经 API 进入应用服务，验证周期并写入 SQLite。主页首次扫描前以 URL 备用身份，获得博主稳定 ID 后以该 ID 去重；详情任务始终以内容地址为任务身份，解析返回的作者 ID 仅作为元数据保存。同一博主的主页与多个详情任务可以共存，重复主页稳定 ID 或相同详情地址受唯一约束限制。名称未填写时采用创建 URL 路径，后续更新 current_name 不改 display_name。

扫描任务通过 `Engine.Scan` 逐条交付媒体，以容量 32 的有界 chan 连接解析生产者与入队消费者。每配置持久下载队列最多提前排队 32 条；队列满时消费者等待，chan 写满后生产者阻塞，停止继续读取引擎输出。新内容和对应下载任务在同一个 SQLite 事务中提交。相同内容 ID 不重复排队。队列认领时应用执行平台上限，扫描不占用下载名额；已发现条目在后续扫描进行期间即可下载。扫描错误保留已入队内容，取消解除通道写入与队列等待。下载通过 `Engine.Download` 在任务专属工作目录运行，成功后按模板归位；再由归档流程移动文件并更新位置。

全量和增量扫描都读取平台当前可获取范围，不承诺平台未返回的历史完整性；增量差别在于新内容 ID 去重。失败内容由任务页面显式重试。没有分页游标优化。

## 五、核心模块

`domain.Engine` 只声明扫描与下载，`domain.Repository` 声明领域记录读写；二者允许后续替换为平台 API 适配器或其他数据库。`service.New(config, repository, engine)` 完成依赖注入，下载和扫描执行不持有 HTTP 依赖。

后端显式锁住任务认领与用户状态操作，耗时引擎运行在锁外。Context 传递取消；服务停止后待恢复任务保留在数据库，重启再入队。每个工作目录以内部任务 ID 命名，后处理失败保留已有文件。

## 六、工程运行

API 使用统一 `{error: ...}` 错误响应，服务状态写标准日志，任务过程按订阅写入日期日志文件，并用任务标识区分并发输出。配置环境变量管理进程路径、地址和首次默认值；用户后续设置保存在数据库，启动不覆盖。

数据库不使用外键或触发器，删除订阅时应用层明确清除相关任务和内容记录，不删除磁盘文件。仅支持当前数据结构：没有数据库版本迁移、旧设置补值、旧客户端设置回退或旧模板别名；初始化参数只在首次创建数据库时写入。结构变更后需手动重建数据库，服务不自动删除或转换已有数据。

调度与媒体入队读取任务和内容索引，归档与数据库提交共用应用锁。扫描采用流式解析与有界背压，下载历史与任务管理在展示层分页。

## 界面展示配置与分页

- `Settings.UI` 独立管理总览展示数量和列表默认页大小，初始化统一来自 `initial-settings.json`；读取时直接使用已保存的当前结构。
- 总览由后端依据设置裁剪最近下载记录；下载历史和任务管理沿用完整数据接口，在展示层分页，不改变下载范围或去重行为。
- `DownloadHistory.vue` 独立于应用入口；`usePagination` 收口页码、条数及轮询时的页码保持；`ListPagination.vue` 共用操作界面，`pagination.ts` 共用分页范围计算。
- 更改系统默认条数立即应用；列表内选择用于本次浏览，切换条数回到首页，记录减少时收回有效页。

## 下载索引与历史展示的职责分离

| 层次 | 职责 | 清空历史后的行为 |
| --- | --- | --- |
| 下载索引 `content_items` | 平台内容身份、完成状态、文件位置、归档状态；增量去重与补全下载的依据 | 完整保留，已有媒体按文件复用 |
| 历史状态 `download_history_cleared` | 保存被清空的内容 ID，控制下载索引的展示投影 | 原子写入清空范围，历史与总览最近下载不再返回这些记录 |
| 下载队列 `tasks` | 执行、取消、重试及日志 | 不受清空影响 |
| 真实文件 | 视频、音频、字幕、评论及归档产物 | 不执行删除、移动或改写 |

保留一份内容索引，避免复制标题、路径、标签与完成状态。历史在领域层有独立的 `DownloadHistoryRepository` 接口，在 `storage/history.go` 查询和管理展示状态，在 `service/history.go` 收口清空与产物呈现。清空属于历史的逻辑删除，索引不是被删除的历史副本，而是扫描去重、任务恢复和归档继续需要的业务数据。

`DELETE /api/contents/history` 通过应用锁与一个 SQLite 语句清空调用时已存在的全部展示记录，返回本次清空数量。历史清空状态可跨重启保存，重复操作不会重复计数。没有版本迁移、旧数据复制或历史回填。新内容不继承清空状态，删除任务配置时显式清理关联的历史状态，不使用外键和触发器。

历史接口与总览最近下载共用历史仓储；扫描、补全和归档仍使用完整索引。普通扫描发现重复项、下载完成后的状态更新和自动归档都不会恢复已清空记录。内容通过补全或重试真正开始新一轮执行时重新进入历史，保持同一个去重身份；清空不取消已在运行的下载。


## 按产物补全与元数据刷新

复用范围是当前配置的同一内容索引，不维护跨任务全局缓存，不扫描旧数据库遗留目录。`engine.Inventory` 对照内容索引中的实际文件及当前任务临时目录，区分视频、额外音频、本地提取音频和字幕语言。完整媒体复用；缺少的产物按当前下载选项获取。info JSON 是可变产物，选择元数据或评论时，手动补全会重新排队已完成内容并刷新该文件；普通全量、增量扫描仍只处理新增内容。

元数据使用独立的 yt-dlp 跳过媒体命令强制刷新；媒体命令不带强制覆盖选项。已有文件可以位于下载区或归档区，补全不把它们复制回工作区。本地提取音频可直接读取已保存视频。新文件沿用已有内容的存放目录，info JSON 覆盖其原索引路径，标题变化不产生第二份元数据。

工作目录与日志共用任务创建时间和编号构成的身份，重试沿用相同目录；不读取旧编号目录。即使后续步骤失败，已完成产物也归位并写入原内容索引；重试复用这些部分成果。成功后移除当前任务内部元数据及临时目录。未完成媒体流和内部元数据不作为用户产物交付。

## 存储管理

日志目录由 `LOG_DIR` 配置，本地默认 `DATA_DIR/logs`，容器默认 `/logs` 并独立挂载。每个订阅每天使用一个 `<任务名称>_<日期>.log` 文件，缓冲写入并按秒刷盘；同一订阅的并发任务共享句柄，每行保留任务 ID。任务管理直接读取订阅日志，不逐条查询内容或打开任务文件。清空日志与句柄写入共用日志锁；活动文件截断，非活动日志删除，任务继续向活动文件追加。旧的每任务日志不迁移或读取。缓存清理与任务认领共用应用锁，只删除无关联及已完成任务目录，保留待执行、运行、失败、取消任务用于续接或重试。不清理下载产物、归档文件、数据库或下载索引，也不迁移旧目录。


## 依赖检查与镜像版本

`internal/config/release.json` 统一管理项目版本和固定依赖，本地构建读取清单，CI 注入候选版本。`scripts/release.py` 读取与比较版本，工作流负责检查、构建、发布和保存。每六小时执行轻量检查，无更新跳过构建；Python 引擎检查 PyPI 非撤回稳定版，FFmpeg 取 Alpine 3.23 两个架构 APKINDEX 的共同可安装版本。

只增加当前主次版本下的补丁号，参考清单与已有标签的最大值，多个依赖更新合并发布。候选提交用于构建，两个架构验证及 GHCR 发布成功后才原子推送清单提交与标签。失败不修改远端清单，工作流串行执行。机器人提交不递归触发构建；不涉及数据库兼容或运行时升级。

## YouTube 付费视频跳过策略

内容索引保留 yt-dlp 的频道 ID 和 `availability`；`subscriber_only`、`premium_only` 作为付费标识，不根据标题或普通登录错误推断。无媒体格式的会员视频也保留扫描结果，由下载阶段记录失败。

策略以频道 ID 为键保存在 `youtube_paid_blocks`，独立于任务配置和界面设置。同频道可以跨主页、详情或播放列表配置共享策略。首次付费内容的引擎执行失败时保存阻断状态；主动取消和本地文件归位失败不触发。调度器在领取并发名额前跳过已识别的付费内容，详情解析后通过只读 `PaidVideoPolicy` 再次检查，避免启动媒体及附属下载。已经运行的任务继续执行。

`skipped` 是独立终态，不计入下载成功或失败；任务、历史和日志保留跳过原因，跳过记录仍属于下载索引。普通扫描、补全与重启不会解除策略，用户显式重试付费条目时解除，并将当前批次中的失败与跳过条目恢复到队列。批量重试在同一应用锁内完成，避免队列启动与再次失败交错。若重新尝试仍失败，再次保存阻断状态。

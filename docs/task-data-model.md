# 任务数据与执行模型

## 数据边界

- 订阅配置：`subscriptions`。订阅和单条下载统一保存平台、地址、周期及产物选项；主页创建只保存，详情创建立即入队一次。
- 帖子任务：`post_tasks`。在所属订阅配置内，以帖子短码或视频 ID 唯一，保存期望资源数量、清单是否完整及整帖状态。一个 Instagram 帖子或一个 YouTube 视频对应一个帖子任务。
- 下载资源任务：`download_items`。以帖子任务、媒体集合 ID、产物类型唯一，分别记录 Instagram 资源或 YouTube 视频、评论/元数据文件、字幕、缩略图、音频和本地音频提取的状态。一个帖子任务包含多个下载资源任务。

`tasks` 是执行尝试/队列账本，`content_items` 是资源文件集合索引。这两张表属于当前初始化设计：执行账本管理排队、取消和重试，文件集合索引管理下载文件与归档位置；帖子任务与下载资源任务管理整帖完整性及资源状态。元数据与评论分别记录期望状态，但共用同一 info JSON 文件与 SDK 阶段；视频分片并发继续使用独立设置。

```text
internal/domain/post.go           帖子任务与下载资源任务模型、平台身份、期望产物、解析前决策接口
internal/storage/posts.go         唯一键核对、帖子任务与下载资源任务事务与状态聚合
internal/storage/schema.sql       当前初始化结构的唯一来源
internal/service/scan_pipeline.go 订阅配置重载、帖子任务核对、解析准备及有界入队
internal/engine/                  单生产者、SDK 身份上报、缓存与下载消费者
internal/httpapi/server.go        订阅配置、帖子任务和下载资源任务只读接口及已有控制接口
```

## 数据流

GUI/CLI 保存订阅配置 → 调度器从数据库加载订阅配置和执行队列 → 执行前再次加载订阅配置和系统设置 → 单生产者枚举帖子身份 → 核对帖子任务 → 未完成时解析并确定期望清单 → 注册下载资源任务 → 下载消费者执行 → 同一事务更新下载资源任务状态并聚合帖子任务状态。

Instagram 在详情接口前及原始帖子转资源前核对帖子任务。YouTube 单地址从 URL 取得视频 ID，不为扫描启动一次完整 SDK 解析；列表使用扁平枚举，新视频由准备阶段取得一次完整信息，消费者复用。

帖子任务完成要求清单已确定、必需的下载资源任务数量等于期望数、全部必需的下载资源任务完成，且执行记录已结束；传输 100% 不替代文件归位与提交。平台明确不提供某可选产物时，下载资源任务记录完成且 `outcome=unavailable`；失败、取消和付费跳过不算下载完成。期望集合减少时保留原资源记录但取消 required，新增子项不会继承已有视频的完成状态。

## 运行与模式

每个平台只有一个获取/解析生产者，Instagram/YouTube 平台队列互相独立。下载并发仍按已约定的媒体条目计算，YouTube 同视频的附属阶段顺序执行；限流窗口、休眠、Cookie 规则继续作用于原共享平台控制器。

每个新条目核对时及后台执行开始前重新读取订阅配置和设置。正在传输的一个条目使用本次执行配置，之后条目加载最新配置，避免在一段下载中途切换产物清单。

全量：跳过已完成的帖子任务，继续枚举后续条目。增量：按最新到历史枚举，整个帖子任务完成后才成为边界；单个已存在的下载资源任务不再截断半个轮播。补全：越过已完成的帖子任务，检查文件缺项并按既有规则刷新所选元数据/评论。配置新增产物时，仅重新排队尚未完成的下载资源任务，已有视频文件复用。

## 初始化与验证

新数据库直接执行 `internal/storage/schema.sql`，并一次写入完整默认设置。客户端随后保存完整当前结构；缺少流水线、休眠窗口或日志行数时返回校验错误，不从已保存数据补入旧值。启动不补齐缺失配置、不关联历史内容、不回放历史阶段事件，也不创建或读取迁移版本表。关联和聚合由仓储事务显式执行，没有外键或触发器。

重新打开当前结构的数据库时，已保存的设置、帖子任务与下载资源任务清单、主键、进度及文件关联保持原值。运行中任务恢复为待执行属于当前队列生命周期；这是重启恢复，不是数据结构迁移。任务详情直接使用下载资源任务中保存的进度和媒体类型，不根据文件反推缺失的阶段记录。

只读 API：`GET /api/subscriptions/{id}/posts`、`GET /api/posts/{id}/downloads`。详情通过仓储的帖子任务与下载资源任务关联查询直接读取整帖状态、期望数量和子项状态，不再从执行账本临时归组；执行账本仅提供操作 ID 与排序时间。

构建前执行 Go 回归、相关 race 检查、Python SDK 适配测试和前端构建；本地使用 `sh scripts/local-deploy.sh` 构建及更新容器。`scripts/post-model-container-smoke.py` 使用正式镜像、真实 SDK、离线 HTTP 素材和十条调试范围验证帖子任务与下载资源任务状态、请求次数、配置更新及重启。

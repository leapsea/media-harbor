# Media Harbor · 版本 1 核心功能与冗余清理

## 核心功能边界

| 功能域 | 必要职责 | 实现位置 |
| --- | --- | --- |
| 任务配置 | 区分主页与详情；识别作者与目录名称；主页首次手动启动后进入周期，详情仅立即执行一次 | `domain/task_mode.go`、`service/app.go`、`service/name.go`、任务编辑器 |
| 扫描与调度 | 全量初始化、增量扫描、补全下载、去重、限量测试、取消和重试 | `service/app.go`、`service/catchup.go`、`service/task_groups.go` |
| 平台引擎 | YouTube 与 Instagram 枚举和下载；作者网页解析；已配置 Cookie 自动使用；引擎输出日志 | `engine/` |
| 文件与历史 | 文件归位、上传日期目录、归档、产物标签、评论与元数据关系、复制文件夹路径 | `service/files.go`、`storage/sqlite.go`、下载历史组件 |
| 展示与设置 | 总览、合并任务管理、历史分页、设置分类、Toast、内部滚动日志 | `web/src/`、`httpapi/`、初始化设置 |

当前单体 Go 服务、SQLite 和 Vue 前端足以支持版本 1。服务层负责业务调度，引擎层负责平台适配，存储层负责持久化，界面组件负责展示与交互；本次不增加新的中间件或架构层。

## 已完成清理

- 删除前端对独立 `/api/tasks` 队列的轮询和无消费者状态、类型。任务管理只读取汇总 `/api/task-groups`；每次刷新由 6 个请求减少到 5 个。底层队列 API 仍供诊断和容器检查使用。
- 总览、下载历史和任务管理共用日期格式函数；总览与下载历史共用任务名称与归档可用状态，减少重复实现。
- 任务管理按 ID 建立汇总映射，避免每个单元格重复搜索整个列表。
- 服务端先按任务配置分组，再筛选和统计各自队列，避免为每个配置反复复制、排序整份队列。当前批次与前 10 条测试范围保持一致。
- 删除只被测试调用的旧 `RenderPath` 包装，测试直接验证生产使用的日期明确的 `renderPathAt`；目录模板仅使用当前 `{directory_name}` 变量。
- 删除旧订阅卡片、旧平台标签、历史标签汇总、完整路径展开、旧 `pre` 日志、未使用三列表单及被覆盖的历史卡片样式。
- 清除重复样式和重复条件，修正过期注释。全局样式由 19,482 字节缩减至 18,110 字节，减少 1,372 字节（约 7.0%）。

## 保留原因

- 全量、增量、补全下载各有业务语义；取消、重试与日志也各有职责，不合并为一个含糊操作。
- 平台作者名称解析与媒体下载需要不同请求方式；无 Cookie 的网页名称解析与使用已配置 Cookie 的下载保持各自职责。
- 引擎实时日志限频与历史日志呈现处理作用于不同输入，均保留。
- 归档跨盘复制用于实现移动语义；文件落位与历史状态更新保留。
- 数据库、下载文件、Cookie 和既有 API 保留。历史截图、需求文档和构建/容器工具用于验证和交付，不作为无用文件删除。
